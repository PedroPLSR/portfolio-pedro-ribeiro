# Contract: i18n (Polylang free)

**Feature**: `002-pre-publish-readiness`  
**Audience**: Implementers (Phase C) + owner configuring Polylang  
**Date**: 2026-08-13  
**Phase**: C. Phases A and B MUST keep working if Polylang is inactive.

## Plugin and stack

| Allowed | Forbidden |
|---------|-----------|
| Polylang **free** on the existing single site | WPML, TranslatePress Pro, other paid i18n |
| Same Docker WordPress | Multisite |
| Pretty permalinks | Query-arg-only language (`?lang=`) as the public scheme |

## Languages and URLs

| Language | Locale | Public URL |
|----------|--------|------------|
| Portuguese (default) | `pt_BR` | `/` (no prefix) |
| English | `en_US` | `/en/` prefix |

## Polylang settings (required)

- Detect browser language: **disabled**.
- Hide default language in URL: **enabled**.
- Language from directory name.
- Do **not** display original content when a translation is missing (never serve PT body as EN).
- Static front page: translate the front page into EN when ready to publish English.

## Missing English home

| Request | Result |
|---------|--------|
| Language control | Omit EN until a **published** EN translation of the front page exists (`hide_if_no_translation` or equivalent). |
| `GET /en/` (or EN home URL) | **404**. Not a Portuguese page with `lang=en`. Not a mixed-language home. |

Theme MUST add a `template_redirect` (or equivalent) 404 if English is requested and the EN front translation is missing/unpublished, in case Polylang would otherwise fall back.

## Language switcher

- Compact header control (PT | EN). Current language indicated (`aria-current` or equivalent).
- MUST NOT replace primary section nav or overpower **PR**.
- On **home**, preserve hash when it is a known section id:

  `/#projetos` ↔ `/en/#projetos`  
  (same for `#topo` `#sobre` `#experiencia` `#now` `#escritos` `#contato`)

- No hash → equivalent home top.
- Inner pages: link to the published translation of **that** page; if none, omit that language in the control (same hide rule).

Hash append is client-side (see [research.md](../research.md) R7) because the fragment is not sent to PHP.

## Content

| Kind | How it is translated |
|------|----------------------|
| Home ACF flex | Sister page (Polylang translation of the static front). Same layout names; omit-empty per language. |
| Menus | Separate menu per language, same locations `primary` / `footer`. Empty location → fallback (gettext labels, same hashes). |
| Theme chrome | Text domain `pedro-ribeiro`; ship `en_US` `.po`/`.mo`. Keep existing PT msgids. |
| Now item titles | Source language (track/game). Labels gettext. Degrade rules unchanged. |
| Escritos | Native posts in the **current** language only. Zero posts in that language → omit section. Do not list the other language’s posts. |
| Section `id`s | Unchanged (see [ui-chrome.md](./ui-chrome.md)). |

`pedro_ribeiro_home_id()` MUST return the current-language front page when Polylang is active so ACF reads the sister flex.

## HTML

- `<html lang="…">` via `language_attributes()` (pt-BR vs en-US).
- No `hreflang` requirement in v1 (optional later); do not block Phase C on SEO extras.

## Regression

- Section order Hero → Sobre → Projetos → Experiência → Now → Escritos → Contato unchanged.
- Now Last.fm / Backloggd behavior unchanged.
- No career-level terms in EN or PT chrome, menus, or ACF.
